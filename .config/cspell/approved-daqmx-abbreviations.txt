# WARNING: Abbreviations are considered part of the DAQmx API and changes to
# the abbreviations should be included as part of an API Review.
#
# Guidelines:
#
# Rejected Abbreviations: For terms we explicitly don't want to abbreviate, list
# the original term as the "abbreviation" (e.g. Actual)
#
# Rejected Full-terms: if a term should not show up,
# 1) include it but don't specify an appreviation (e.g. "Cal").  These exist
# when they are part of an abbreviated phrase.  We have to list the individual
# parts of the phrase in this file as well.
# 2) Include make the abbreviated form an expansion of itself (e.g. CJC).
#
# Units: The general rule is to use the same units that industry typically uses for
# the associated sensors/measurements. So, when a customer looks at their sensor data
# sheet, they should not have to translate from one unit terminology to another.
